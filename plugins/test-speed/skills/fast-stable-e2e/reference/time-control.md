# 시간에 기대는 화면을 시험이 쥐는 법

마감·만료·자동 저장·재접속 대기·「n분 전」 표시처럼 시간이 흘러야 바뀌는 화면이 있으면, 시간을 그냥 흐르게 두지 않는다. 시험이 시간을 쥐고, 감을 때만 시간이 가게 한다.

시간을 혼자 빠르게 흐르게 두면(만료를 몇 ms로 줄이는 식) 이런 일이 생긴다.
- 화면이 본 상태와 서버 상태가 어긋나 흔들린다. 단추를 누르는 순간 서버는 이미 다음 상태다.
- 사람 손이 닿아야 하는 창(30초 마감)이 몇 ms 만에 닫힌다. 그래서 그 시험만 느린 설정의 서버를 따로 띄우게 된다.
- 여정 하나가 수십 초가 되고, 결국 E2E만 예산 예외를 둔다.

한 프로젝트에서 잰 값: 시간을 시험이 쥐게 바꾼 뒤 20초짜리 여정 하나가 시험 9개(각 0.5~1.7초)가 됐고 흔들림은 0이었다.

## 시간의 출처마다

| 시간의 출처 | 쥐는 법 |
|---|---|
| 브라우저 타이머(`setTimeout`·`Date`·애니메이션) | Playwright `page.clock` — `install()` 뒤 `runFor`·`fastForward`·`pauseAt`. 서버는 건드리지 않는다 |
| 서버 코드의 「지금」(만료·마감을 `now()`와 비교) | 시계를 주입할 수 있게 한다. 단위·백엔드 시험은 `time-machine`·`freezegun`(Python), `vi.useFakeTimers`·`sinon`(JS). E2E 스택은 시험 설정에서만 열리는 경로로 서버의 「지금」을 옮긴다 |
| 배경 작업 주기(작업 큐의 정기 작업, cron, 아웃박스 적용기) | 시험 설정에서 주기를 끄고 「한 번 돌기」를 시험 전용 경로로 부른다. 끌 수 없으면 주기를 0.05초쯤으로 줄인다 |
| 서버가 직접 도는 주기 루프(시뮬레이션·게임 엔진 등) | 루프에 멈추기·다시 돌리기·N번 감기 손잡이를 단다. 루프가 라이브러리 것이면 **라이브러리 기능으로 넣는다** — 앱에서 내부 메서드를 덮어쓰면 라이브러리가 바뀔 때 조용히 깨진다 |

## 공통 규칙

- **감기는 결과가 반영된 뒤 돌아온다.** 감기 요청의 응답이 오면 그 시간 동안의 처리가 끝나 있어야 한다. 그다음 화면은 이벤트 도우미(`waitForMessage`·`waitFor`)로 기다린다. 「감고 잠깐 자기」를 되풀이하지 않는다.
- **시험 전용 경로는 시험 설정에서만 열린다.** 운영 설정에서 404인지 백엔드 시험으로 못 박는다.
- **E2E 스택은 시간이 멈춘 채 시작한다.** 사람 손 창이 사람을 기다린다.
- **시간을 멈추면 숨은 경합이 드러난다.** 스냅샷과 스트림 사이를 시각으로 거르던 코드는 시간을 멈춘 순간 접속 뒤 갱신을 전부 잃는 것으로 드러났다. 시험에서 「접속 뒤 한 번 감기」로 덮지 말고 코드를 고친다(순번으로 거르기 — django-asgi 플러그인의 `sse-snapshot-stream` 참고).
