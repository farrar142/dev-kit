# 목 스택과 화면 찍기

화면 티켓마다 작업자가 목 서버·스크린샷 스크립트를 새로 짜면, 매번 수십 턴이 같은 준비에 든다. 저장소에 한 번 만들어 두고 모든 화면 티켓이 쓴다.

## 구성

| 조각 | 하는 일 |
|---|---|
| `mock/scenes/*.json` | 장면. 실제 서버의 스냅샷·응답 출력을 **생성기가 뽑는다**. 손으로 쓰지 않는다 |
| 생성기 + 시험 | 백엔드 시험이 장면을 다시 뽑아 파일과 **키 구조**를 비교한다. 서버 직렬화가 바뀌면 실패하고, `..._WRITE=1`로 다시 쓴다 |
| `mock/server.mjs` | 장면을 내는 목 API. 모르는 GET은 404, 모르는 쓰기는 `{}`를 낸다. 장면의 `routes['METHOD /path']`로 끝점을 더한다. 실시간 스트림을 흉내 내면 `say` 같은 지연도 둔다 |
| `mock/stack.mjs` | `startStack(scene)` → `{ app, mock, close }`, `launchBrowser()`. → [examples/stack.mjs](examples/stack.mjs) |
| `mock/shot.mjs` (`pnpm shot <장면> --name N [--mockup 시안.png]`) | 1280×800과 390 폭으로 찍고, 시안이 있으면 시안·실제를 나란히 붙인 `-vs.png`를 만든다 |

## 지켜야 할 것

- **프로세스는 그룹째 내린다.** vite는 `pnpm` 아래 자식으로 뜬다. 부모에게만 신호를 보내면 vite가 고아로 남고, 지운 워크트리에 `.vite` 캐시를 다시 만든다.
  - `spawn(..., { detached: true })`로 띄우고 `process.kill(-pid)`로 그룹째 내린다.
  - `exit`·`SIGINT`·`SIGTERM` 걸이로, 예외로 끝나도 내리게 한다.
- **목은 실제 응답에서 뽑는다.** 손으로 쓴 목은 실제 서버가 늘 채우는 필드를 빠뜨린다. 그러면 화면이 `undefined`를 그리거나 하얗게 죽는데, 제품 버그가 아니라 목 버그다. 생성기 + 구조 비교 시험으로 막는다.
- **화면 조각은 오류 경계로 감싼다.** 응답이 어긋나도 앱 전체가 하얘지지 않고 그 조각만 「열지 못했어요」가 된다. 목에서 드러난 결함이 운영에서 전체 장애가 되지 않게 하려는 것이다.
- **장면이 모자라면 장면을 고친다.** 필요한 사람·상태가 장면에 없다고 「확인 못 함」으로 넘기지 않는다. 생성기에 장면을 더하거나 `mock.scene`을 살아 있는 채로 고친다(`parts`, `routes`).
  - 임시 장면을 손으로 만들 때는 상태끼리 맞물리게 한다. 「앉음」 표시를 켰으면 자리도 소파로 옮긴다. 그러지 않으면 증거 스크린샷이 거짓 모습이 된다.
- **비교는 시안 PNG와 나란히.** 배치·치수까지 맞춘다. 고칠 때마다 전체를 다시 찍어 읽지 말고, 바뀐 부분만 `clip`으로 찍는다. 전체 비교는 마지막에 한 번 한다.
- **Playwright 브라우저 판이 안 맞으면** `~/.cache/ms-playwright/`에서 가장 새 chromium을 쓴다(`cachedChromium()`).
- **E2E를 대신하지 않는다.** 이 도구는 화면 확인·스크린샷용이다.
