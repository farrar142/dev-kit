# 시험이 쥐는 서버 시계

## 왜

E2E에서 시간을 혼자 빠르게 흐르게 두면(틱 1ms, 짧은 만료 등) 세 가지가 생긴다.
- **흔들림:** 화면이 본 상태와 서버 상태가 어긋난다. 예를 들어 버튼은 「여기」라고 하는데 서버는 「너무 멂」을 낸다.
- **시간 창 문제:** 사람 손이 닿아야 하는 창(45초 마감)이 몇 ms 만에 닫힌다. 그래서 따로 느린 엔진을 띄워 돌리게 된다.
- **예외 늘리기:** 한 판 여정이 20초씩 걸리면, 결국 E2E만 예산 예외를 둔다.

시험이 시계를 쥐면 이 셋이 사라진다. 틱 루프 서버에서 잰 실제 숫자로는 20초 여정 하나가 시험 9개, 각 0.5~1.7초가 됐고 흔들림은 0이었다.

## 시간의 출처마다 쥐는 법

원칙은 하나다. **시험이 시간을 쥔다.** 시험이 감을 때만 시간이 가고, 감기는 그 결과가 반영된 뒤에 돌아온다. 쥐는 방법은 시간이 어디서 오느냐에 따라 다르다.

| 시간의 출처 | 쥐는 법 |
|---|---|
| 브라우저 타이머(`setTimeout`·`Date`·애니메이션) | Playwright `page.clock`(`install`·`runFor`·`pauseAt`). 서버는 건드리지 않는다 |
| 서버 코드의 「지금」(만료·마감을 `now()`와 비교) | 시계를 주입할 수 있게 하고, 시험 설정에서 고정·이동 가능한 시계로 바꾼다. Python은 `time-machine`이나 `freezegun`(단위·백엔드 시험), E2E 스택은 시험 전용 경로로 「지금」을 옮긴다 |
| 배경 작업 주기(Celery beat, cron, 아웃박스 적용기) | 시험에서는 주기를 끄고, 시험 전용 경로로 「한 번 돌기」를 부른다. 끌 수 없으면 주기를 0.05초로 줄인다 |
| 서버의 자체 틱 루프(게임·시뮬 엔진) | 루프에 멈추기·다시 돌리기·N틱 감기 손잡이를 단다. → [reference/tick-loop-server.md](reference/tick-loop-server.md). **엔진 라이브러리를 쓰면 라이브러리 기능으로 넣는다.** 앱에서 내부 메서드를 덮어쓰지 않는다. tickworld는 farrar142/tickworld#71 |

공통 규칙:
- 시험 전용 경로·명령은 시험 설정에서만 열린다. 운영 설정에서 404인지 백엔드 시험으로 못 박는다.
- E2E 스택은 시간이 멈춘 채 시작한다.
- 시험 걸음 `advanceClock`·`tickUntil`·`openGame`을 공용 파일에 둔다. → [examples/steps.ts](examples/steps.ts)

## 시험을 짜는 법

- **3초 예산, 예외 없음.** 여정은 화면 흐름마다 시험 하나로 나눈다. 앞 화면까지는 **API로 준비**하고, 화면으로 되풀이하지 않는다.
  - 가입·만들기 화면은 그 화면을 덮는 시험 하나에서만 화면으로 돈다.
- **준비 요청은 Node `fetch`와 쿠키 단지로.** Playwright 요청 맥락은 한 번에 약 20ms, Node fetch는 약 5ms다. 끝나면 쿠키를 브라우저 맥락에 옮겨 같은 사람으로 화면을 연다.
- **서버를 거친 화면 넘김은 `tickUntil(locator)`로 기다린다.** 「한 틱 감고, 그 화면을 잠깐 기다리기」를 되풀이한다. 서버가 틱에서 집계·넘김을 한다면 이게 맞다.
- **사람 손 창은 따로 돌리지 않는다.** 시계가 멈춰 있으니 창이 사람을 기다린다.
- **E2E 브라우저 설정:**
  - 걷기 같은 연출 애니메이션은 `contextOptions: { reducedMotion: 'reduce' }`로 건너뛴다. 제품에 그 갈래가 있어야 한다.
  - 외부 글꼴·분석 스크립트 요청은 `context.route(...).abort()`로 막는다. 망이 느리면 그것만으로 `page.goto`가 3초를 넘긴다.
- **E2E 스택 설정:** 빠른 비밀번호 해셔, 배경 적용기(아웃박스) 주기 0.05초, Postgres `trust`·tmpfs.
- **스택 용량:** 데이터에 한도가 있으면(방 17개 등) 시험 수 × 사람 수를 확인한다. 다시 돌릴 때는 스택을 새로 띄운다.

## 흔들림 함정 (실제로 겪은 것)

- **「단추 개수를 세고 누르기」:** 투표가 마감되며 단추가 사라지는 순간에 세면, 사라진 단추를 끝없이 기다린다. 개수를 미리 세지 말고 「보이는 첫 단추를 누르거나, 다음 화면이 오면 그만」으로 짠다. 시계를 멈추면 이런 경합을 매번 재현할 수 있어서 원인 찾기가 쉬워진다.
- **시각으로 거르는 스트림:** 스냅샷과 스트림 사이를 시각으로 거르면, 시계를 멈췄을 때 접속 뒤에 오는 갱신이 전부 버려지는 것으로 드러난다. 시험에서 「접속 뒤 한 번 감기」로 덮지 말고 스트림을 고친다(순번으로 거르기). 처방은 django-asgi 플러그인의 `sse-snapshot-stream` 참고 문서에 있다.
