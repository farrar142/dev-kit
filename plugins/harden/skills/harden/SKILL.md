# harden — 재발 방지는 장치부터, 문서 한 줄은 마지막

산문 규칙은 가장 약한 방어다. 읽히지 않을 수 있고, compact로 잊히고, 낡아도 아무도 모른다.
같은 실수가 다시 나오면 「어떻게 하면 이 실수를 **할 수 없게** 만들까」를 먼저 묻는다.

## 사다리 — 위에서부터 따지고, 되는 첫 칸에서 멈춘다

| 칸 | 무엇 | 예 |
|---|---|---|
| 1. 구조 | 틀린 길이 아예 없게 한다(API·폴더 경계·기본값·도구가 거절) | 필수 인자가 없으면 CLI가 실행을 거절한다. 위험한 동작을 기본값에서 빼고 명시 플래그로만 연다 |
| 2. 정적 검사 | 린트·타입·CI 검사가 실패시키고, 메시지가 고칠 방법을 말한다 | 금지된 import를 린트 규칙으로 막는다. 공개 저장소에 비밀 꼴이 들어가면 CI가 실패한다 |
| 3. 시험 | 그 실수를 재현하는 시험 하나 | 사고를 재현하는 회귀 시험. 「무조건 성공하는 가짜」 대신 실제 서비스의 조건부 동작을 흉내 내는 시험 대역 |
| 4. 훅 | 에이전트의 도구 호출을 막거나 고쳐 준다 | token-diet `read-guard`(큰 파일 통째 읽기 거절)·`block-heredoc`, leak-guard(공개 저장소로 나가는 유출 차단), context-cap |
| 5. 스크립트 | 여러 단계 절차를 한 명령으로 묶는다 | issue-track `wait-ci.py`(CI를 손으로 반복 확인하는 대신 끝날 때 한 번 알림) |
| 6. 산문 | 판단이 필요해서 기계로 못 막는 것만 | 「범위 밖 리팩터는 하지 않는다」 |

- 막는 장치의 **실패 메시지는 원인과 고칠 방법**을 말한다(「X 금지 — 대신 Y를 써라」). 에이전트는 그 메시지를 읽고 스스로 고친다. 이유만 말하고 길을 안 주면 같은 시도를 되풀이한다.
- 장치를 만들 수 있는데 지금 시간이 없으면, 산문으로 임시로 막고 **장치를 만드는 이슈**를 같이 연다. 에이전트가 만들면 훅·검사 하나는 대개 한 시간 안이라 「나중에」는 대개 핑계다.

## 산문으로 남길 때 (6칸)

한 줄에 셋을 넣는다: **무엇**, **왜(사고 날짜·출처)**, **지울 조건**.

```
- 배포 전에 마이그레이션 dry-run을 돌린다 — 빠뜨려 운영 DB 잠금이 났다(2026-03-02, #123). 배포 스크립트가 dry-run을 하게 되면 지운다.
```

- 이미 있는 줄을 고칠 수 있으면 새 줄을 더하지 않는다.
- 장치가 생기면 그 산문 줄을 **같은 작업에서 지운다**. 장치와 산문이 둘 다 남으면 산문은 곧 거짓이 된다.

## 공개 저장소에 넣는 장치

장치(훅·검사·시험) 안에 내부 호스트 이름·주소·저장소 이름·토큰을 쓰지 않는다 — 막으려던 유출을 장치가 한다. 구체 금지어 목록은 저장소 밖(로컬 설정 파일·비공개 저장소)에 두고, 저장소에는 일반 패턴과 「목록을 어디서 읽는가」만 둔다. 예: leak-guard는 일반 패턴만 내장하고 사용자 금지어는 `~/.config/leak-guard/patterns.txt`에서 읽는다.

## 보고

재발 방지를 했으면 보고에 한 줄 넣는다:

```
재발 방지: <칸 이름> — <무엇을 했나> (지운 산문: <있으면>)
```

장치를 못 만들고 산문으로 막았으면 그 이유와 장치 이슈 번호를 쓴다.
