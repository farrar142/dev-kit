# 클라우드 방화벽 — 기본값과 조이기 체크 포인트

세 클라우드 모두 「인스턴스 단위 규칙」과 「서브넷 단위 규칙」이 겹쳐 있다. 바깥에서 닿으려면 **두 층 모두**가 허용해야 하고, 안쪽 통신도 같은 규칙을 지난다. 조이기 전에 지금 규칙을 통째로 기록하고, 사설 대역 허용부터 남긴 뒤, 한 번에 하나씩 바꾸고 바깥에서 다시 잰다.

기본값은 콘솔 마법사·템플릿·계정 설정에 따라 다를 수 있다. 아래는 일반 기본값이며, 실제 상태는 반드시 그 계정에서 직접 확인한다.

## OCI (Oracle Cloud Infrastructure)

| 층 | 단위 | 상태 |
|---|---|---|
| 보안목록(Security List) | **서브넷 전체** | 상태유지 규칙(규칙마다 상태비유지 선택 가능) |
| NSG(Network Security Group) | VNIC(인스턴스 인터페이스) 묶음 | 상태유지, 더 세분 |

- VCN을 만들면 **기본 보안목록**이 서브넷에 붙는다. 흔한 기본 규칙: 원격 접속 포트를 모든 출발지에 허용, 일부 ICMP 허용, VCN 내부 대역의 일부 허용, 아웃바운드 전부 허용. 「기본이 닫혀 있다」고 가정하지 않는다.
- **보안목록이 서브넷 전체를 지배한다** — 외부 유입뿐 아니라 **같은 VCN 안 호스트끼리의 통신**도 이 규칙을 지난다. 공개 허용을 좁히다 VCN 내부 허용이 함께 사라지면 다른 사설 호스트의 DB·캐시로 가는 길이 끊긴다.
- 실제로 적용되는 것은 보안목록과 NSG 규칙의 **합집합**이다. 한쪽에서 지워도 다른 쪽에 허용이 남아 있으면 열려 있다.
- 인스턴스 이미지에 따라 호스트 방화벽(iptables·firewalld)이 기본으로 켜져 있기도 하다 — 클라우드 규칙과 별개로 확인한다.

체크 포인트:
- [ ] 서브넷에 붙은 보안목록 전부와 인스턴스 VNIC의 NSG 전부를 나열했다.
- [ ] **VCN 내부 대역(사설 CIDR) 허용 규칙을 먼저 넣거나 있는지 확인했다** — 그다음에 공개(모든 출발지) 규칙을 좁힌다.
- [ ] 모든 출발지 허용은 웹 포트만 남았다. 원격 접속은 관리 대역으로 좁혔다.
- [ ] 세분이 필요한 것(DB 포트는 앱 호스트에서만 등)은 보안목록 대신 NSG로 옮겼다.
- [ ] 공개 서브넷·사설 서브넷 구분: DB 같은 것은 공개 IP 없는 사설 서브넷에.

## AWS

| 층 | 단위 | 상태 | 기본 |
|---|---|---|---|
| 보안그룹(Security Group) | ENI(인스턴스 인터페이스) | **상태유지**, 허용 규칙만 | 새 보안그룹: 인바운드 전부 차단, 아웃바운드 전부 허용 |
| NACL(Network ACL) | 서브넷 | **상태비유지**, 허용·거부·번호 순서 | 기본 NACL: 양방향 전부 허용 |

- 보안그룹은 상태유지라 응답 트래픽을 따로 허용할 필요가 없다. NACL은 상태비유지라 응답이 돌아오는 **임시 포트 범위**를 아웃바운드(또는 인바운드)에 허용해야 한다. NACL을 조이다 응답 경로를 막는 실수가 흔하다.
- 보안그룹 규칙은 출발지로 **다른 보안그룹**을 가리킬 수 있다 — 「앱 그룹에서만 DB 포트」처럼 주소 대신 그룹으로 사설 통신을 허용하면 대역 변경에 덜 깨진다.
- **기본 VPC의 함정**: 계정마다 리전별 기본 VPC가 있고, 서브넷이 모두 공개 서브넷(인터넷 게이트웨이 경로 + 공개 IP 자동 할당)이다. 기본 보안그룹은 같은 그룹끼리 모든 통신을 허용한다. 마법사가 만든 보안그룹은 원격 접속을 모든 출발지에 여는 경우가 있다.

체크 포인트:
- [ ] 인스턴스 ENI마다 붙은 보안그룹 전부(여러 개면 합집합)를 나열했다.
- [ ] 모든 출발지(IPv4·IPv6 둘 다) 허용 규칙을 찾아 웹 포트 외에는 지웠다.
- [ ] DB·캐시는 출발지를 앱 보안그룹으로 지정했다.
- [ ] NACL을 손댔다면 임시 포트 범위의 응답 경로가 열려 있다.
- [ ] 기본 VPC를 쓰는지, 공개 IP 자동 할당이 켜져 있는지 확인했다.

## GCP

| 층 | 단위 | 상태 |
|---|---|---|
| VPC 방화벽 규칙 | VPC 네트워크 전체, 대상은 태그·서비스 계정·전체 인스턴스 | 상태유지, 허용·거부·우선순위 |
| (선택) 계층형 방화벽 정책 | 조직·폴더 | 위에서 먼저 평가 |

- 모든 VPC에 지울 수 없는 **암묵 규칙** 둘: 이그레스 전부 허용(implied allow egress), 인그레스 전부 거부(implied deny ingress). 둘 다 가장 낮은 우선순위다.
- **기본(default) 네트워크**에는 미리 채워진 규칙이 있다: 내부 대역 전부 허용, 원격 접속·원격 데스크톱·ICMP를 모든 출발지에 허용. 기본 네트워크를 그대로 쓰면 「기본이 닫혀 있다」는 가정이 틀린다.
- 규칙 대상은 **네트워크 태그** 또는 **서비스 계정**. 태그는 인스턴스 편집 권한만 있으면 붙일 수 있어 경계로 약하다 — 경계가 중요한 규칙은 서비스 계정 기반으로.
- 방화벽 규칙은 서브넷이 아니라 **네트워크 전체**에 걸린다. 대상 지정이 「모든 인스턴스」인 규칙을 찾아본다.

체크 포인트:
- [ ] 기본 네트워크를 쓰는지 확인했다. 쓰면 미리 채워진 공개 허용 규칙을 좁혔다.
- [ ] 내부 대역 허용 규칙이 남아 있다(사설 통신용) — 그다음에 공개 규칙을 좁힌다.
- [ ] 출발지가 모든 주소인 규칙마다 대상(태그·서비스 계정)과 포트를 확인했다.
- [ ] 조직·폴더의 계층형 정책이 VPC 규칙보다 먼저 허용·거부하지 않는지 봤다.
- [ ] 방화벽 규칙 로깅을 켜 실제로 맞는 규칙을 확인할 수 있다.

## 공통

- 클라우드 규칙 + 호스트 방화벽 + 프로세스 바인딩 주소, 세 곳을 따로 본다. 하나만 보고 판정하지 않는다.
- IPv6 규칙을 따로 본다 — IPv4만 좁히고 IPv6 모든 출발지 허용이 남는 일이 흔하다.
- 판정은 언제나 바깥 두 지점에서 다시 잰 결과로 한다.
