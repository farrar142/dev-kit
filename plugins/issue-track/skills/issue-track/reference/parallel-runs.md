# 병렬로 돌릴 때의 함정

티켓 여럿을 의존성 체인으로 묶어 체인마다 워크트리 서브에이전트 하나씩 나란히 돌리고, 끝에 조율자가 한데 합치는 실행(예: `dispatch-tickets` 류 스킬)에서 한 프로젝트가 밟은 것들이다. 대부분 「초록으로 보이는데 사실이 아닌」 모양이라 진단이 늦다.

## 체인(서브에이전트) 지시서에 넣을 것

- **「`/code-review`(리뷰 스킬)를 포크하지 말고 자기 diff를 직접 읽어라」.** 서브에이전트가 리뷰를 포크하면 그 결과는 서브에이전트가 아니라 **최상위 세션으로** 배달된다. 체인은 오지 않을 답을 기다리며 커밋하지 않은 채 멈춘다(한 체인은 941줄을 워크트리에만 둔 채 멈췄다). 리뷰 에이전트가 체인 자신의 시험과 같은 시험 DB를 놓고 다투기도 한다.
  - 멈춘 체인은 `SendMessage`로 깨워 「결과는 안 온다, 직접 읽고 커밋하라」고 말한다.
  - 조율자에게 도착한 리뷰는 그 코드를 가진 체인으로 넘긴다. 조율자가 직접 고치면 체인 브랜치 밖으로 나간다.
- **브라우저 자동화 도구가 싱글턴이면 쓰고 닫는다.** 첫 에이전트가 안 닫으면 락이 남아 뒤 체인이 전부 튕긴다. 동시에 돌면 서로의 탭을 뺏으니 자기 오리진 URL을 확인하고 돌아오게 한다.
- **문서의 시험 건수·실측 표는 체인이 건드리지 않는다.** 체인마다 자기 시점 값을 써서 충돌이 나고 셋 다 틀린다. 통합에서 한 번 잰다.
- **컨테이너는 프로젝트 이름을 늘 명시한다**(`docker compose -p <체인 몫 이름> …`). 지시서에 오프셋을 박아도 `-p` 없이 친 `docker compose down` 하나가 공유 dev 스택을 통째로 내린 적이 있다. 체인마다 포트 오프셋을 경로 해시로 정하는 저장소면 **띄우기 전에 계산해 겹침을 본다** — 프로젝트 이름까지 같으면 포트 충돌이 아니라 남의 스택을 조용히 인수한다.
- **전체 시험은 티켓 커밋 직전에만, 워커 수는 체인 수에 맞춰.** 체인 여럿이 `-n auto` 전체 시험을 동시에 돌리면 코어를 서로 뺏어 한도 시험이 떨어진다.
- **필요한 컨테이너만 띄운다.** 스택 셋을 동시에 띄우다 OOM이 나 워커의 질문 메시지가 배달 전에 죽은 적이 있다.

## 조율자 쪽 — 통합 지점

- **새로 만든 통합 워크트리는 의존성 설치부터**(`pnpm install --frozen-lockfile` 등). `node_modules`가 없으면 typecheck·시험·dev 서버가 「not found」로 죽는데 코드 탓처럼 보인다. 컨테이너를 올린 뒤 호스트의 앱별 `node_modules`가 비는 일도 있다 — 게이트 직전에 한 번 더 설치하면 안전하다. 판정은 앱별 폴더까지 0항목인지로 한다(pnpm 워크스페이스는 루트가 비어 있는 것이 정상이다).
- **`명령 | tail` 뒤의 `$?`는 `tail`의 것이다.** 게이트 다섯이 모두 실패했는데 `exit=0`을 찍었다. 파이프 없이 받거나 `PIPESTATUS`.
- **통합은 보고된 해시가 아니라 브랜치의 실제 tip으로.** 체인이 tip을 보고한 뒤 커밋을 하나 더 얹은 적이 두 번 있다. 보고에 없는 커밋은 따로 읽는다.
- **배경 폴러를 완료의 유일한 신호로 삼지 않는다.** 가장 확실한 신호는 `git log --oneline <기준>..<체인 브랜치>`와 그 워크트리의 `git status`다. 오래 걸린다 싶으면 브랜치부터 본다(워커가 이미 끝났는데 폴러가 빈 출력으로 끝나 아무것도 진행되지 않은 적이 있다).
- **폴링에서 맞지 않은 메시지를 버리지 않는다.** 워커의 질문이 그 안에 있으면 워커는 영원히 기다린다. 거르는 기준은 dispatch id가 아니라 메시지 종류(`worker_done`·`question`·`escalation`)다 — 기동 상태 메시지에도 같은 id가 들어 있다.
- **상수·필드를 지우는 티켓은 의미 충돌을 낳는다.** 한 체인이 상수를 지웠는데 다른 체인은 옛 tip 위에서 계속 썼다. 파일이 안 겹쳐 git은 깨끗이 합쳤고 합친 결과만 ImportError로 죽었다. **통합 뒤 전체 시험을 반드시 다시 돌린다.**
- **체인은 E2E가 치는 API 호출부를 못 본다.** API 입력 모양을 바꾼 체인이 E2E 스펙을 옛 모양으로 남겼다. 통합에서 `grep -rn <옛 필드> <e2e 폴더>`.
- **합류 체인(다른 체인 둘을 합친 체인)은 충돌 해결을 들고 온다.** 최종 통합은 합류 체인을 그 부모 대신 합치면 같은 충돌을 다시 풀 필요가 없다. 통합 워크트리에서 미리 시험 병합해 충돌 파일을 알아 두면 순서를 정하기 쉽다.
- **여러 리뷰어의 교차 검증이 파일을 가로지르는 버그를 잡는다.** 세 파일에 걸친 권한 우회를 리뷰어 넷이 따로 찾았다 — 어느 한 체인의 시야에도 안 들어오던 것이다.
- **PR·병합 상태는 말하기 직전에 직접 친다.** 워커의 중간 알림은 그 순간의 사실이다.
